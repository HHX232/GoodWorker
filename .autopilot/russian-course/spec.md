# Спецификация — курс «Русский язык», первая волна

Реализует R01–R10 из `manifest.md`. Ярус: **T2** (большая многотикетная сборка,
реальный контент в проде-БД, внешняя генерация изображений, новый тип файла).

## Область первой волны

4 блока в порядке из R06, каждый — отдельный тикет (см. `tickets/`):

| Блок | Категория (`parentSlug`) | Листовых тем | Из них уже в БД |
|---|---|---|---|
| 01 Орфография | `orthography` | 8 | 2 (`spelling-words`, `prefixes-suffixes`) |
| 02 Морфология | `morphology` | 10 | 2 (`parts-of-speech`, `participles-gerunds`) |
| 03 Синтаксис | `syntax` | 10 | 2 (`simple-sentence`, `complex-sentence`) |
| 04 Пунктуация | `punctuation` | 7 | 4 (`commas`, `colon`, `dash`, `quotation-marks`) |

Итого 35 листовых тем. Полный список тем с описанием/идеей объяснения/идеей проверки —
в каждом файле `tickets/0N-*.md` (там же, где их будет читать исполнитель, а не здесь).

**Вне первой волны** (следующие волны, не строим сейчас):
- Блок «Фонетика/графика/орфоэпия» (R05, deferred — отдельный будущий курс).
- Новые ветки Лексика, Словообразование, Стилистика, Развитие речи, подготовка к ОГЭ/ЕГЭ —
  черновик их тем сохранён в истории диалога, но не зафиксирован тикетами: решаем в
  следующей волне, когда первая пройдёт ревью.

## На каждую листовую тему (R08, R09)

- 1–2 поста-объяснения (`Post`, категория = эта листовая тема).
- 2 теста (`Test` + `TestCategory` на ту же категорию): один короткий (5–8 блоков),
  один большой/итоговый (12–20 блоков) — использует типы блоков теста, уместные теме
  (см. `interfaces.md`, конкретные типы решает исполнитель тикета по месту).
- 1 PDF-шпаргалка на тему (см. `interfaces.md` — генерация и upload).
- Один из постов темы несёт обложку — изображение через kie.ai (R02, R10).
- Один из постов темы прикрепляет оба теста (блок `TEST_LINK`) и PDF-шпаргалку
  (блок `FILE_LIST`) — контент не рассыпан по несвязанным записям, ученик видит тему
  как одну карточку с объяснением → тестами → шпаргалкой.

## На каждый блок (R09)

1 сводный PDF-«оглавление» блока — не пересказ, а список тем блока с одной строкой
правила на тему (компактная навигация «что вообще есть в этом разделе»), без
привязки к конкретному посту (просто загружается в S3, ссылку кладём в сообщение о
готовности тикета — куда её вставить в интерфейс, решит следующая волна/пользователь).

## Технические контракты

Полные, проверенные по коду детали — в `interfaces.md`. Кратко:
- Категории — расширение `prisma/seed.ts`-подобного дерева (та же форма `CategoryNode`),
  но отдельным идемпотентным скриптом на тикет (см. ниже), не правкой самого `seed.ts`.
- Посты — `Post.content = {blocks: PostBlock[]}`, блоки `TEXT`/`MEDIA`/`TEST_LINK`/`FILE_LIST`
  (`src/shared/types/Post/Post.type.ts`).
- Тесты — `Test.content = {description, blocks: TestBlock[]}`, типы блоков из
  `TaskBlockType` (`src/shared/types/Tasks/TaskType.type.ts`), payload каждого типа —
  читать в `src/features/Tasks/TaskObjects/*.tsx` перед использованием.
- Файлы (PDF, изображения) — прямой аплоад через `src/shared/s3/s3Client.ts`
  (`PutObjectCommand`), без похода в `/api/upload` (нет браузерной сессии в seed-скрипте).
- Изображения — CLI `velsvisual` (ключ уже настроен локально), скачать → загрузить в S3.
- PDF — `pdf-lib` (уже зависимость проекта, использовать вместо HTML→PDF/новых пакетов).
- Автор всех записей — `teacher@seed.dev` (существующий сид-аккаунт, паттерн лукапа по
  email как в `prisma/seedContent.ts`/`seedErrors.ts`, не хардкод ID).

## Gate G2

Независимый читатель (следующая сессия ревью тикета) должен по брифу+этой
спецификации не находить ничего лишнего: каждое из R01–R10 либо реализовано в
первой волне, либо явно вынесено за неё строкой выше с указанием, где оно будет.
