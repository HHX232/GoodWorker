# Спецификация: лендинг PDF→Test — 3 принципиально разных варианта с переключением

## Задача

У преподавателя уже есть материалы с вопросами в PDF/Word. Чтобы объяснить,
что инструмент PDF→Test превращает такой файл в готовый онлайн-тест за минуту,
нужен рекламный лендинг. Но неизвестно, какой визуальный язык сработает лучше —
поэтому нужно не «один лендинг», а **несколько принципиально разных версий**,
между которыми можно переключаться и выбрать сильнейшую.

## Решение

Три самостоятельных одностраничных лендинга (открываются двойным кликом, без
сборки), с одинаковым содержанием и разными визуальными мирами, плюс плавающий
переключатель `V1 · V2 · V3`, который есть на каждой странице и переносит на тот
же раздел соседнего варианта. Приоритет — чёрно-белый, много воздуха, акцент на
визуале и анимации; hero показывает процесс «PDF → тест» с всплывающими
указателями; каждая секция отличается от предыдущей. Победителя потом интегрируем
в Next.js — это отдельный заход, вне рамок.

**Три мира** (каждый — свой шрифт, ритм, приём анимации, но все Ч/Б):

- **V1 — Swiss / Kinetic Type.** Строгая типографическая сетка, огромный гротеск,
  чёрное на белом, волосяные линии, максимум воздуха. Появление — маска-развёртка
  строк, отрисовка линий, счётчики.
- **V2 — Terminal / Blueprint.** Тёмный доминантный фон, моноширинный шрифт для
  данных/логов, точечная сетка, угловые засечки, скан-линия. Появление — «декод»/
  печатная машинка, отрисовка чертёжных линий, скан-вайп между секциями. (Эволюция
  текущего технического стиля инкумбента, доведённая до конца.)
- **V3 — Cinematic / Gallery.** Крупный высококонтрастный serif (Didone),
  драматичный Ч/Б, большие планы и негативное пространство, «киношная» медленная
  моторика. Появление — параллакс, масштабный подъём, sticky-пиннинг с морфингом.

## Решения по реализации

- **Формат.** 3 самостоятельных HTML-файла + `index.html` + общий `shared/switcher.js`.
  Каждый вариант self-contained (инлайн CSS/JS), делится только переключателем и
  каноничным копирайтом. *Почему:* цель — сравнить и выбрать; отдельные файлы
  собираются быстрее, честно сравниваются и не трогают продакшн.
- **Расположение.** `ForNewDesign/prototypes/` — это дизайн-разведка для выбора
  направления. *Почему:* пользователь просил дизайн-файлы держать в `ForNewDesign`,
  а прод-код появится позже при интеграции победителя.
- **Шрифты** (self-host через Google Fonts `<link>`; работает при онлайне, есть
  fallback). *Почему:* нужен характер лица, а не системный дефолт; список
  training-дефолтов impeccable (Space Grotesk/Mono, Playfair, IBM Plex, DM…) избегаем.
  - V1 Swiss: **Archivo** (+ Archivo Expanded для дисплея), fallback `Helvetica Neue, Arial`.
  - V2 Terminal: **JetBrains Mono** (данные/логи — легитимный mono, совпадает с инкумбентом), fallback `ui-monospace, monospace`.
  - V3 Cinematic: **Bodoni Moda** (Didone-дисплей) + **Archivo** (текст), fallback `Georgia, serif`.
- **Палитра.** База монохром у всех. Один сигнальный акцент на мир, точечно (не
  заливки): V1 — чистый чёрный + один тонкий акцент подчёркивания; V2 — off-white на
  near-black + микро-акцент «живого» курсора/скана; V3 — глубокий Ч/Б + без цвета,
  контраст несёт тон. *Почему:* R02 требует Ч/Б без цветастых блоков.
- **Hero-процесс (R04/R05).** Анимированный макет: PDF-страница (фейковые строки) →
  скан-полоса → распознавание → морфинг в карточки вопросов (single/multi/match…).
  Выносные callout'ы с leader-линиями к деталям. Драйвер — scroll-trigger (пиннинг
  секции у V3; прогресс по скроллу у V1/V2). На месте будущего видео — этот макет,
  помечен `data-placeholder`. *Почему:* видео генерируется позже (KIE_API_KEY не задан).
- **Reveal-словари (R03.1).** Общее ядро — IntersectionObserver, ставит `.is-in`.
  Приём — на совести мира: V1 clip/mask-развёртка + счётчики; V2 decode/typewriter +
  отрисовка линий + scan-wipe; V3 параллакс + scale-rise + sticky-морф. Всё уважает
  `prefers-reduced-motion`.
- **Переключатель (R11).** Общий `shared/switcher.js` + разметка `<nav data-switcher>`
  на каждой странице. Подсвечивает активный вариант по имени файла; при клике сохраняет
  долю прокрутки в `sessionStorage['pdfland:scrollRatio']` и восстанавливает на целевой
  странице. *Почему:* сравнивать удобно на том же месте страницы.
- **Верификация.** Прототип статичный — юнит-сьют непропорционален. Проверка: (1)
  визуальный смотр desktop+mobile по craft-floor (скриншоты, финальное ревью
  impeccable-стиля), (2) смоук: страницы открываются без ошибок в консоли, ссылки
  переключателя резолвятся, reduced-motion отключает движение. *Почему:* цель —
  визуальный выбор, а не поведенческий контракт.

**Швы для проверки (минимум):** контракт переключателя (`<nav data-switcher>` + ключ

`interfaces.md` дословно, чтобы 3 параллельных исполнителя не разошлись.

## Предложенные варианты reveal-приёмов (R03.1 — «предложи варианты»)

Бриф просит именно **предложить варианты** появления элементов. Предлагаем меню из
шести приёмов; три мира демонстрируют разные подмножества, чтобы заказчик увидел их
вживую и выбрал (это часть выбора «лучшей версии»):

| Приём | Что делает | Где показан |
|---|---|---|
| **Mask-развёртка** | строка/блок раскрывается из-под маски (clip-path) снизу вверх | V1 |
| **Счётчик** | число добегает от 0 к значению при въезде | V1 |
| **Decode / typewriter** | текст «декодируется» из шума в финальные буквы | V2 |
| **Line-draw** | SVG/бордер-линии прочерчиваются (stroke-dashoffset) | V2 |
| **Scan-wipe** | переход между секциями горизонтальной скан-полосой | V2 |
| **Scale-rise + parallax** | элемент поднимается и проявляется с параллаксом слоёв; sticky-морф | V3 |

Заказчик может оставить понравившиеся приёмы у победителя. Все — с `prefers-reduced-motion`.

## Контент (наполнение экранами, R06) — единый для всех вариантов

Секции по порядку (каждая — визуально иначе поданная, R09). Для каждой — элементы
внутри (чтобы исполнитель не додумывал):

1. **Hero.** Элементы: крупный заголовок; подзаголовок (1 строка); анимация процесса
   PDF→тест (документ → скан-полоса → карточки вопросов) с 3–5 указателями-callout'ами;
   primary-CTA «Загрузить PDF»; вторичная ссылка «Как это работает»; метка-скролл-хинт.
2. **Как это работает.** Элементы: 3 шага (Загрузка → Распознавание → Готовый тест),
   у каждого — номер/иконка-приём в стиле мира, заголовок, 1 строка. Разная сетка, чем в hero.
3. **Типы вопросов.** Элементы: 6 форматов (одиночный, множественный, сопоставление пар,
   ввод текста, упорядочивание, верно/неверно), у каждого — мини-визуал формата + тег +
   1 строка. Подача НЕ одинаковыми карточками-иконками (craft-floor), а сеткой с разным ритмом.
4. **Готовый тест.** Элементы: макет прохождения — прогресс-бар, навигация по вопросам
   (сетка номеров), пример вопроса с выбранным ответом, метка автопроверки. Один крупный визуал.
5. **Профиль ошибок.** Элементы: демо-карточка ученика (имя — «пример», класс, N тестов,
   N ошибок), список слабых тем с группировкой (тема → тип задания → счётчик), подпись
   «пример, не реальные данные». Один информативный визуал.
6. **Честные лимиты.** Элементы: короткая полоса-сравнение Гость (5 вопросов, PDF) vs
   Авторизованный (20 вопросов, PDF + VIP: DOCX/TXT/RTF/ODT). Минимум текста.
7. **FAQ.** Элементы: 3–4 пары вопрос/ответ (что с картинками и формулами; насколько
   точно; нужен ли аккаунт; сколько занимает). Аккордеон или столбец.
8. **Финальный CTA + футер.** Элементы: крупная фраза «Загрузи первый документ»,
   кнопка «Загрузить PDF», тонкий футер (название продукта, ссылки-заглушки).

Точные строки копирайта — в `interfaces.md` (copy deck), единые для всех вариантов.
Текста мало (R07); в каждой секции ведёт визуал/приём (R08).
