# Что уже построено

Ярус T0 — один контекст, без нарезки на таски. Границы — из `spec.md` → «Границы и швы».

## Правила проекта

- Стек: Next.js (App Router) + Prisma + PostgreSQL, SCSS-модули, `next-intl`, TanStack Query, `lucide-react`.
- Тестового раннера нет — верификация: `npm run build` (типы) + смоук в браузере (`npm run dev`).
- i18n: namespace `files`, добавлять ключи одновременно во все 4 локали (`en`, `ru`, `hi`, `zh`).
- Недостающая зависимость обычно не ставится (возвращаем `BLOCKED`) — здесь исключение: `pdf-lib` добавлена лениво (`import('pdf-lib')`), по прецеденту `docx-preview`/SheetJS из итерации 4 tutor-files.

## Границы

- `AnnotatedPages` — без изменений, `exportStrokes()`/`hasChanges()` уже публичны, переиспользуются как есть.
- `ReviewModal` — новая функция сборки исправленного PDF (байты оригинала + `exportStrokes()` → `pdf-lib`), новый проп `onReupload: (file: File) => Promise<boolean>`.
- `FilesShell` — передаёт `onReupload={f => uploadFiles([f])}` в `<ReviewModal>` (переиспользует существующую `uploadFiles`, никакой новой логики квоты/VIP/тостов).

## Построено (T0, один проход)

- `uploadFiles()` в `FilesShell.tsx` теперь возвращает `Promise<boolean>` (раньше `void`) — успела ли загрузка целиком. Существующие вызовы (drag&drop, инпут-загрузка) результат игнорируют, поведение не изменилось; новый вызов из `onReupload` использует его, чтобы не показать «успех» поверх уже показанного тоста об ошибке квоты/VIP.
- `ReviewModal.tsx`: кнопка «Загрузить в директорию» в тулбаре — видна только для `viewer === 'pdf'` и только когда есть новые (несохранённые) мазки текущей сессии (`hasMarks`, стейт, обновляемый в `onChange`, а не чтением `pagesRef.current` во время рендера — react-hooks/refs ругается на второе). `uploadCorrected()`: `exportStrokes()` (уже существовал) → `fetch` тех же байт PDF, что и `/content` → `pdf-lib` (`PDFDocument.load` + `embedPng` + `drawImage` на всю страницу, по одной на каждую отмеченную страницу) → `pdfDoc.save()` → `new File(...)` → `onReupload`.
- Новая зависимость: `pdf-lib` (^1.17.1), лениво через `import('pdf-lib')` внутри `uploadCorrected()` — не в общем бандле.
- i18n: `files.reuploadButton`/`reuploadSuffix`/`reuploadDone` в `messages/{en,ru,hi,zh}.json`.
- Проверено: `tsc --noEmit` и `eslint` по всему проекту — чисто; `npm run dev` + логин `teacher@seed.dev` + `GET /files` — бандл собирается и рендерится без ошибок в консоли сервера. Ручной клик «нарисовать мазок → нажать кнопку → увидеть второй файл» вживую в браузере не прогонялся (нужен реальный PDF на проверке и рисование пером) — стоит один раз проверить руками.

## Итерация 2 — редактор docx (по запросу пользователя после оценки)

Пользователь сам нашёл и назвал пакет: `@docx-editor.dev/react` + `@docx-editor.dev/core` (Apache-2.0, ~60k загрузок/неделю, полностью клиентский — .docx байты внутрь, .docx байты наружу, никакого document-сервера/аккаунта). Проверено вручную перед установкой: README, package.json (peer `react ^18|^19`), реальный движок на ProseMirror + HarfBuzz(wasm) для шейпинга шрифтов.

- **Схема:** `TutorFile.derivedFromId String?` (миграция `20260927204113_tutor_file_derived_from`) — плоский маркер, не Prisma-relation. Стоит только на файле, который редактор сохранил «как новый»; на оригинале всегда `null`.
- **Правило сохранения (ответ пользователя на брифинг-вопрос):** первое сохранение сессии редактирования создаёт новый файл рядом с оригиналом (`<имя> (исправлено).docx`, `derivedFromId` = id оригинала) через уже существующий `POST /api/tutor-files/files` (расширен необязательным полем `derivedFromId` в FormData, проверяется, что исходный файл принадлежит тому же репетитору). Второе и последующие сохранения **в той же открытой сессии** идут в новый `PATCH /api/tutor-files/files/[id]/content` — перезаписывают именно этот файл (тот же id, значит те же гранты/ссылки/проверки на него не рвутся). `PATCH` отказывает (400 `NOT_DERIVED`), если у файла нет `derivedFromId` — оригинал никогда не перезаписывается этим путём, даже если фронт ошибётся.
- **`PATCH /api/tutor-files/files/[id]/content`** — FormData `{file}`, тот же порядок, что и `POST` (S3 put → запись в БД → переиндексация текста через `after()`), тот же контракт квоты (`{file, usedBytes, quotaBytes}`), тот же набор кодов ошибок (`VIP_REQUIRED`/`QUOTA_EXCEEDED`/`FILE_TOO_LARGE`). Старый S3-объект не удаляется (как везде в проекте).
- **`LibraryFile.derivedFromId`** добавлен в клиентский тип и в единственный мэппер `toFile()` (`readModel.ts`) — оба места, откуда клиент узнаёт форму файла (`/library`, `/search`).
- **`src/widgets/Files/DocxEditorModal/DocxEditorModal.tsx`** — новый компонент, монтируется через `next/dynamic(..., {ssr:false})` из `FilesShell` (весь `@docx-editor.dev/*`, ~7 МБ, не попадает в основной бандл — фетчится только при открытии редактора). Грузит байты через тот же `GET /files/[id]/content`, что и превью; ref (`DocxEditorRef.save(): Promise<ArrayBuffer|null>`) на кнопку сохранения пакета (`onSave` проп — без него у пакета своя кнопка «скачать», с ним поведение целиком наше). Внутри сессии хранит `target` (текущий файл), переключает его на только что созданный после первого сохранения — второе сохранение в той же сессии уже видит `target.derivedFromId` и уходит в overwrite.
- **`FilesShell.uploadFiles()`** — сигнатура расширена (`opts?: {derivedFromId}`, возвращает `LibraryFile[] | null` вместо `boolean`) для переиспользования тем же кодом (квота/VIP/тосты) и загрузкой-как-новый из редактора; старый вызов из `ReviewModal` адаптирован (`(await uploadFiles([f])) !== null`). Новая `overwriteFile()` — тонкая обёртка над `PATCH`, с тем же переиспользуемым `uploadErrorToast()`.
- **Пункт меню «Редактировать»** (`FileCard`, иконка `FileEdit` — новая, отличная от `Pencil`/переименования) — только для `viewerFor(mime,name)==='docx'`, только у репетитора (`canManage`), как и «Проверить»/«Сделать тест».
- **Не реализовано и не входит в объём этого пакета:** xlsx/pptx-редактирование («и подобных файлов» из запроса) — библиотека умеет только `.docx`; чужая интернационализация UI редактора — `@docx-editor.dev/i18n` не поставляет `ru`-каталог (есть только en/de/fr/he/hi/id/pl/pt-BR/tr/zh-CN), поэтому сам редактор (тулбар/меню) остаётся на английском, а не на языке сайта — сознательный компромисс, чтобы не переводить сторонний пакет вручную.
- **Важная находка окружения (не моя правка, задокументировано для памяти):** локальная dev-БД этого чекаута разошлась с `prisma/migrations/` — часть таблиц tutor-files (`StorageSettings`, `TutorFileReview`, `TutorFileOpen`, `TutorFolderOpen`, `TutorFolderLink`) физически отсутствуют в локальной Postgres (только `TutorFile`/`TutorFolder`/`*Grant` есть, из более раннего, несквошенного прогона миграций на ветке кошелька, шарящей ту же БД). `prisma migrate dev`/`db push` в этом состоянии предлагают **удалить** реальные таблицы/данные Кошелька (`WalletTransaction` с 51 строкой и т.п.) — ни то, ни другое не выполнялось. Новую колонку (`derivedFromId`) внёс точечно через `prisma db execute` + `migrate resolve --applied`, не трогая остальной дрейф. Живой клик «открыть редактор → напечатать → сохранить» через реальный аплоад поэтому не прогонялся (упирается в отсутствующий `StorageSettings`, не в этот код); проверено иначе — `tsc --noEmit`, `eslint`, полный `npm run build` (Turbopack, прод-сборка) чистые, без предупреждений от `@docx-editor.dev/*`.
- Self-check пакета сделан вручную (нет юнит-теста, T0-масштаб): `npm view`/`npm pack` пакетов, чтение README и `.d.ts`, реальный `npm run build` прошёл.
