# Спецификация: Перезалив отредактированного PDF + оценка docx-редактора

## Задача

Репетитор проверяет сданную учеником работу (PDF) в модалке «Проверка» — рисует пометки поверх страниц. Сейчас, чтобы дать ученику «второй, исправленный» файл рядом с оригиналом, репетитору пришлось бы вручную выгрузить PDF со своими правками, скачать его на диск и заново загрузить в ту же папку через обычную загрузку — три шага и ожидание вместо одного клика.

Отдельно — вопрос, можно ли то же самое (редактирование прямо на сайте) сделать для .docx.

## Решение

В модалке «Проверка» появляется кнопка «Загрузить в директорию»: она видна, как только репетитор нарисовал пометки на PDF-странице в этой сессии. Один клик — пометки впечатываются прямо в страницы PDF, и рядом с оригиналом в той же папке появляется второй файл `<имя> (исправлено).pdf`. Оригинал не трогается. Скачивать и заново загружать не нужно.

Для docx — только письменный ответ: что можно сделать, чего это стоит, без кода (решено на брифинге — пользователь выбрал вариант «только оценка»).

## Решения по реализации

1. **«Редактирование PDF» = существующая `ReviewModal`/`AnnotatedPages`** (перо поверх страниц, идея 1 из прошлых итераций). Отдельного «PDF-редактора» в проекте нет и не создаётся — кнопка встраивается в этот же экран. *Почему:* это и есть единственное существующее «редактирование PDF», на которое ссылается бриф.

2. **Кнопка активна только когда есть новые, ещё не сохранённые мазки в этой сессии** (`AnnotatedPagesHandle.hasChanges()` — уже существует). Пометки, сохранённые в *прошлой* сессии проверки (`layers`/kept layers — уже загруженные на S3 PNG-слои), в этот PDF не впечатываются. *Почему:* впечатать чужой (ранее загруженный) PNG-слой пришлось бы через `<canvas>`, а без гарантированных CORS-заголовков S3-бакета это тайнтит canvas и ломает экспорт непредсказуемо — тогда как свежие мазки уже рисуются в том же canvas и не покидают браузер до экспорта. Если нужно включить и старые пометки — их видно на холсте, репетитор может обвести их пером заново, либо это отдельная доработка (см. «Вне рамок»).

3. **Слияние делает `pdf-lib`** (новая зависимость, лениво — `import('pdf-lib')`, по образцу `docx-preview`/SheetJS из итерации 4 — «зависимости не ставим» снимается для конкретной, разрешённой пользователем задачи): грузим оригинальные байты PDF с того же `/api/tutor-files/files/[id]/content`, что уже использует `AnnotatedPages` для показа; для каждой страницы с новыми мазками — переиспользуем уже существующий `exportStrokes()` (даёт PNG на страницу, с прозрачным фоном), встраиваем PNG (`embedPng` + `drawImage` на всю страницу — прозрачность обеспечивает, что исходное содержимое страницы просвечивает под пометками) и сохраняем итоговые байты (`pdfDoc.save()`).

4. **Загрузка нового файла — через уже существующий `POST /api/tutor-files/files`** (FormData `file`+`folderId`), тот же эндпоинт, что и обычная загрузка в `FilesShell` — не создаём новый роут. `folderId` — папка, в которой лежит открытый в проверке файл (`file.folderId`); в `FilesShell` это всегда текущая открытая папка, поэтому `ReviewModal` получает уже готовую функцию `uploadFiles([file])` через новый проп `onReupload`, а не пишет свою логику квоты/VIP/тостов — она вся уже есть и переиспользуется как есть (включая предупреждение о перелимите).

5. **Имя нового файла** — `<исходное имя без расширения> (исправлено).pdf`. Оригинал не переименовывается и не удаляется; дубликаты имён в папке уже штатно допустимы (файлы различаются по id, не по имени).

6. **Действие независимо от вердикта/оценки.** Кнопка не требует выставленного статуса «Принято/На доработку» и не сохраняет вердикт — это отдельное, аддитивное действие; существующая кнопка «Сохранить проверку» не меняется.

7. **Только PDF, не картинки.** `AnnotatedPages` также рисует пометки поверх изображений (`viewer === 'image'`), но в брифе речь только о PDF — кнопка не показывается для картинок (см. «Вне рамок», A01).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R03 — редактирование .docx на сайте | Решено на брифинге пользователем («только оценка, без кода»). Оценка: <br>**(а) Полноценный редактор «как в Word»** требует отдельного document-сервера (OnlyOffice Document Server / Collabora Online) — свой хостинг, лицензия/self-host, WOPI-протокол для чтения-записи файла сервером; это отдельный инфраструктурный проект, не строчка кода в существующий `docx-preview`. <br>**(б) Упрощённый редактор текста** технически возможен уже сегодня на уже установленных зависимостях: `docx` (npm, уже в проекте — сейчас используется для генерации, не парсинга) + добавить `mammoth` (docx→HTML) → редактирование как обычного текста (contentEditable/rich-text) в браузере → сборка нового `.docx` обратно через `docx`. Работает для простого текста; таблицы, сложные стили, картинки и разрывы разметки при обратной сборке скорее всего «поедут» или потеряются — это редактор простого текста, а не замена Word. Отдельная сборка, сопоставимая по объёму с текущей (T1–T2). <br>**(в) Ничего не делать сейчас** — выбор пользователя. |
| A01 — та же кнопка «Загрузить в директорию» для отредактированных изображений | В брифе — только PDF. `AnnotatedPages` уже умеет рисовать поверх картинок, поэтому расширение дешёвое, но не заказано; оставляю на будущее по запросу |
| Впечатывание в новый PDF пометок из *прошлой* сессии проверки (`kept layers`) | См. «Решения по реализации» п.2 — риск тайнта canvas без гарантии CORS у бакета; отдельная доработка, если понадобится (например, прокси-эндпоинт для чтения layer-PNG с CORS-заголовками) |
