## Что должно заработать

Кнопка-скрепка открывает системный выбор файла; изображение показывает
превью-миниатюру перед отправкой и сжимается на клиенте (canvas → JPEG)
перед загрузкой; не-изображение показывает имя файла и иконку. Кнопка ГС
записывает голосовое через `MediaRecorder` и отправляет как аудио-сообщение,
воспроизводимое обычным `<audio>` в пузыре. Лимит 10 МБ после сжатия —
с понятной ошибкой и на клиенте, и (второй линией защиты) на сервере.

## Из брифа, дословно

> «Все файлы само собой для начала сжимаем, публикация до 10 мб»

## Критерии приёмки

- [ ] Скрепка → выбор файла → превью перед отправкой (миниатюра для фото,
      имя+иконка для остального) → отправка создаёт сообщение с вложением,
      видимое в истории
- [ ] Изображения сжимаются на клиенте перед загрузкой (новый хелпер рядом с
      уже существующим `compressImageToBase64`, но отдающий `File`/`Blob`
      через `canvas.toBlob`, а не data URL — для загрузки в S3 нужен файл)
- [ ] Файл, который после сжатия (или без него — для не-изображений) больше
      10 МБ, не отправляется — тост с понятным текстом лимита, и на клиенте,
      и отдельно проверено что сервер тоже отклоняет вложение тяжелее лимита
- [ ] Голосовое: запись через `MediaRecorder`, кнопка показывает состояние
      записи, остановка → отправка как аудио-сообщение с проигрывателем в
      истории
- [ ] Отказ в доступе к микрофону — тост с объяснением, а не немая кнопка
- [ ] Реально проверено через настоящий dev-сервер (не только чтение кода):
      отправлено фото, отправлен документ, отправлено голосовое — все три
      появились в истории диалога у обеих сторон (репетитор/ученик)
- [ ] Тёмная и светлая тема на новых элементах (превью вложения, индикатор
      записи)
- [ ] Коммит только своих файлов, `git push origin main`
