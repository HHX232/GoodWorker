## Что должно заработать

Выбор диалога в списке (из тикета 02) открывает справа реальную переписку:
история сообщений пузырями (свои справа, чужие слева, время), textarea снизу
с отправкой по Enter (Shift+Enter — перенос строки), сообщения приходят и
уходят по-настоящему через API тикета 01. Открытый диалог обновляется сам —
опрос раз в 3 секунды, только пока вкладка активна.

## Критерии приёмки

- [ ] Открытие диалога показывает реальную историю сообщений с сервера
- [ ] Пустой диалог (сообщений ещё нет) — заглушка-приглашение написать
      первым, не пустой белый экран
- [ ] Текст отправляется по Enter, Shift+Enter переносит строку, отправленное
      сообщение появляется в истории без перезагрузки страницы
- [ ] Пустой ввод (ни текста, ни выбранного вложения) — кнопка отправки
      неактивна
- [ ] Двойной быстрый клик «отправить» не создаёт два одинаковых сообщения
      (поле блокируется на время запроса)
- [ ] Композер: слева направо — textarea, кнопка-скрепка (пока без
      обработчика), кнопка ГС (пока без обработчика), кнопка отправки
- [ ] Пока диалог открыт, новые сообщения от собеседника появляются сами в
      течение нескольких секунд без ручного обновления страницы; опрос
      останавливается, когда вкладка не активна (`document.visibilityState`)
- [ ] `MessageBubble` умеет разложить сообщение по типу (`text` / что-то с
      `attachmentType` / что-то с `eventType`) даже если пока реализован
      только текстовый вариант — остальные типы не должны падать, просто
      не показаны красиво (заглушка на один рендер-цикл, тикеты 04/05 её
      заменят)
- [ ] Публичные пропсы `ConversationView`/`MessageBubble`, которыми
      пользуются тикеты 04, 05 и 06, дописаны в `interfaces.md`
- [ ] Тёмная и светлая тема
- [ ] Коммит только своих файлов, `git push origin main`
