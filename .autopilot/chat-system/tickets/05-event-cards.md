## Что должно заработать

Три разных момента в системе, которые уже существуют, получают четвёртый
побочный эффект — сообщение с `eventType` в чате того самого ученика:

1. `app/api/homework/route.ts` — там, где уже вызывается
   `createNotification({type: HOMEWORK_ASSIGNED, ...})` на каждого ученика
   домашки, добавь вставку `ChatMessage` в диалог (teacherId из сессии,
   studentId = `a.studentId`) с `eventType: "HOMEWORK_ASSIGNED"` и тем же
   `payload` (`homeworkId`, `assignmentId`), что уже уходит в уведомление.
2. `app/api/services/route.ts` — там же, где создаётся `PERSONAL_SERVICE`
   уведомление при создании персонального предложения, добавь аналогичную
   вставку `ChatMessage` с `eventType: "PERSONAL_SERVICE"`.
3. `tg-bot/src/scheduler.ts` (`sendPaymentReminders`) — там, где уже
   создаётся `Notification` через `createPaymentReminderNotification`
   (см. `tg-bot/src/db.ts`), добавь третий побочный эффект: get-or-create
   диалог (raw SQL, та же техника, что уже используется для `Notification`
   в этом файле) и вставку `ChatMessage` с `eventType: "PAYMENT_REMINDER"`,
   `eventPayload` = то же самое, что уже уходит в текст Telegram-сообщения
   (`teacherName`, `unpaidCount`, `totals`).

В интерфейсе — `MessageBubble` (тикет 03) для сообщений с непустым `eventType`
рендерит не обычный текстовый пузырь, а `EventCard`: заголовок, иконка по
типу события, короткое описание, и — только для `HOMEWORK_ASSIGNED` — ссылка
«Открыть задание» на `/homework/[assignmentId]`. Для `PERSONAL_SERVICE` и
`PAYMENT_REMINDER` ссылки нет (у этих типов сейчас нет отдельной страницы —
так же, как у существующих platform-уведомлений тех же типов).

## Из брифа, дословно

> «Когда репетитор создает для ученика ДЗ, персональное предложение услуги,
> подходит срок напоминания оплаты то в чате появляется красивое
> уведомление карточка-превью события такого»

## Критерии приёмки

- [ ] Назначение домашки реальному ученику (curl или через существующий UI)
      создаёт и уведомление, и сообщение-карточку в чате с тем же учеником —
      проверено просмотром реальной истории сообщений через API тикета 01
- [ ] Создание персонального предложения услуги — аналогично, карточка
      появляется в чате
- [ ] Наступление checkpoint-момента напоминания об оплате (тот же механизм,
      что уже шлёт Telegram и platform-уведомление) — аналогично добавляет
      карточку в чат; проверено тем же способом, что уже проверялся сам
      механизм оплаты в этой сессии (симуляция recurring-событий с
      `everyNLessons`, реальный вызов cron-функции)
- [ ] Карточка визуально отличается от обычного текстового сообщения —
      заголовок, иконка, для ДЗ — рабочая ссылка на `/homework/[assignmentId]`
- [ ] Тёмная и светлая тема на карточке
- [ ] tg-bot: изменения закоммичены и запушены **внутри `tg-bot/`** отдельно
      от основного репозитория (`git -C tg-bot add ... && git -C tg-bot commit
      ... && git -C tg-bot push origin main`), затем в основном репозитории
      обновлён и закоммичен только сам сабмодуль-указатель (`git add tg-bot`)
- [ ] Коммит основного репозитория — только свои файлы, `git push origin main`
