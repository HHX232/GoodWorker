# Спецификация: Баланс/кошелёк вместо прямой покупки VIP

## Задача

Сейчас единственный способ получить доступ к части AI-фич (генерация формул на доске,
план урока, фото-режимы PDF→Тест) — это VIP «всё или ничего»: нет VIP — фича закрыта
целиком (403), есть VIP — фича доступна без ограничений и без учёта того, во что она
реально обходится сервису (реальные токены DeepSeek стоят реальных денег на каждый вызов).

Учитель или ученик, которым нужен один план урока или одна формула, вынуждены либо
покупать VIP целиком (со всеми его непрофильными плюшками — лимит участников звонка,
свои курсы, число учеников), либо не получают фичу вообще. А для владельца платформы
это означает, что дорогие AI-вызовы VIP-пользователей ничем не ограничены и не покрываются
доходом с конкретного вызова.

## Решение

Пользователь пополняет собственный баланс (пока — через мок-оплату, без реального
платёжного провайдера) на любую сумму в долларах. Баланс живёт отдельно от VIP:

- **Баланс тратится только на AI-вызовы** (7 существующих эндпоинтов) — списывается
  реальная себестоимость вызова в токенах DeepSeek (с учётом пик/непик тарифа и разницы
  кэш-попадание/кэш-промах) плюс процент наценки, настраиваемый переменной окружения.
- **VIP остаётся отдельной характеристикой аккаунта** — она больше не блокирует доступ
  к AI-фичам (см. G01), а решает только то, что и раньше решала помимо AI: лимит
  участников в звонке, свои курсы, число учеников и т.п.
- **Пополнение от $5 даёт VIP-бонус** — `floor(сумма_в_долларах / 5)` месяцев VIP
  начисляется поверх текущего срока, и это не расходует баланс: вся внесённая сумма
  целиком остаётся доступна на AI-вызовы.
- Пользователь в любой момент видит текущий баланс и историю пополнений/списаний.
- Недостаточно средств на вызов — понятная ошибка «нужно ещё $X», вызов к AI-провайдеру
  вообще не делается (деньги провайдера не тратятся впустую).

Разбор ошибок после видеозвонка остаётся полностью бесплатным — баланс к нему не имеет
отношения.

## Решения по реализации

### Схема данных (Prisma)

- `Teacher.balanceCents Int @default(0)`, `Student.balanceCents Int @default(0)` — храним в целых центах, не `Float` (в отличие от уже существующего `VipTransaction.amount`, где это не исправляем — вне периметра).
- Новая модель леджера:

```prisma
enum WalletTransactionType {
  DEPOSIT
  AI_DEBIT
}

model WalletTransaction {
  id                 String                @id @default(uuid())
  teacherId          String?
  studentId          String?
  userRole           Role
  type               WalletTransactionType
  amountCents        Int      // всегда положительное число — знак задаёт type
  balanceAfterCents  Int
  endpoint           String?  // для AI_DEBIT: какой из 7 эндпоинтов
  shortfallCents     Int?     // для редкой гонки из R14i.2 — сколько реально не хватило
  description        String
  createdAt          DateTime @default(now())
  teacher            Teacher? @relation(fields: [teacherId], references: [id], onDelete: SetNull)
  student            Student? @relation(fields: [studentId], references: [id], onDelete: SetNull)

  @@index([teacherId, createdAt])
  @@index([studentId, createdAt])
}
```

  Не переиспользуем `VipTransaction` для списаний — у неё смысл «VIP-дни», а не деньги
  (это уже было решено в диалоге до брифинга). При пополнении ≥$5 дополнительно пишем
  строку в `VipTransaction` (`type: DEPOSIT` — значение уже есть в существующем enum
  `TransactionType`, просто не использовалось), тем же способом, каким это уже делает
  `app/api/teacher/vip/activate/route.ts` для промокодов.

### Ценообразование (`src/shared/lib/wallet/pricing.ts`)

Единственное место с тарифами — правится в одном файле, не по роутам.

- Тарифы DeepSeek (дословно из ответа пользователя, за 1M токенов):
  - вход, кэш-промах: $0.15 (непик) / $0.30 (пик)
  - вход, кэш-попадание: $0.003 (непик) / $0.006 (пик)
  - выход: $0.60 (непик) / $1.20 (пик)
- Пик = 01:00–04:00 UTC и 06:00–10:00 UTC, Пн–Пт (официальный анонс DeepSeek, действует
  с 16:00 UTC 16 авг. 2026); всё остальное — непик, включая выходные целиком. Исключение
  китайских праздников из пик-часов **не автоматизировано** — см. «Открытые места».
- Наценка — `process.env.AI_MARKUP_PERCENT` (например `"50"` → +50% сверху себестоимости
  токенов); если переменная не задана — наценка 0% (себестоимость без наценки), не ошибка.
- `computeCostCents(usage, at)` — чистая функция, себестоимость + наценка, округление
  вверх до целого цента (никогда не округляем вниз в пользу пользователя).
- Раздельного тарифа на vision-модель (`deepseek-v4-flash-vision-exp`) пользователь не
  называл — применяется та же таблица токенов, что и для `deepseek-chat` (см. «Открытые
  места»).
- Путь без `DEEPSEEK_API_KEY` (бесплатная модель `openrouter/free`) не тарифицируется —
  себестоимость неизвестна, считается $0, списания не происходит.
- Оценка верхней границы для preflight (`estimateMaxCostCents(endpoint, promptChars, at)`) —
  по каждому из 7 эндпоинтов: длина промпта (уже известна на входе) как верхняя оценка
  входных кэш-промах токенов + фиксированный потолок выходных токенов на эндпоинт (близкий
  к существующему `maxTokens`/практическому размеру ответа этого эндпоинта — где `maxTokens`
  не передаётся явно, берётся консервативная оценка по формату ответа: короткий LaTeX ~200
  токенов, JSON-план урока ~2000 токенов и т.п.).

### Захват реального usage из AI-вызова (`src/lib/openrouter.ts`)

DeepSeek API поддерживает `stream_options: {include_usage: true}` в потоковом режиме —
последний SSE-чанк содержит `usage.prompt_cache_hit_tokens`, `usage.prompt_cache_miss_tokens`,
`usage.completion_tokens`. Меняем сигнатуру:

```ts
callAI(system, user, opts) -> Promise<{ content: string; usage: AIUsage | null }>
callVisionAI(system, images, user, opts) -> Promise<{ content: string; usage: AIUsage | null }>
```

`usage: null`, если провайдер не вернул usage (openrouter-фолбэк, либо поле отсутствует) —
в этом случае себестоимость такого вызова не считается (см. выше — $0, не начисляем).
Если usage есть, но без разбивки кэш-хит/промах — весь `prompt_tokens` трактуется как
кэш-промах (консервативно дороже, а не заведомо дешевле, чем реально).

Меняются все 7 вызывающих роутов (сигнатура из `const raw = await callAI(...)` в
`const { content, usage } = await callAI(...)`) — сама структура промптов/парсинг ответа
(`parseJSON`) не меняется.

**D01 (обнаружено при сборке тикета 01):** `callAI`/`callVisionAI` вызываются ещё в 6 местах
за пределами этого брифа — `src/lib/postAI.ts` (6 точек вызова), `src/shared/lib/gemini.ts`,
`app/api/calendar/google/import/route.ts`, `app/api/check-answer/route.ts`,
`app/api/tests/generate-title/route.ts`, `scripts/ingest-curriculum.ts`. Смена сигнатуры на
`{content, usage}` ломает их компиляцию, хотя ни один не относится к 7 платным эндпоинтам
и не должен тарифицироваться. Решение: механически адаптировать все 6 под новую сигнатуру
(`const { content: raw } = await callAI(...)`, без добавления preflight/списания — они
остаются полностью бесплатными, как и были). Это правится тикетом 05.

### Списание и защита от гонки (`src/shared/lib/wallet/wallet.ts`)

Атомарное условное списание через `updateMany` (родное для Prisma, без сырого SQL):

```ts
const result = await prisma.teacher.updateMany({
  where: { id: teacherId, balanceCents: { gte: costCents } },
  data: { balanceCents: { decrement: costCents } },
})
// result.count === 1 → списано штатно
// result.count === 0 → баланс уже не хватает (гонка) → см. R14i.2
```

При `count === 0` (гонка после preflight — крайне редкий случай, но не игнорируется):
второй `updateMany` без условия `gte`, обнуляющий баланс (`set: 0`), и запись в леджер
с `shortfallCents = costCents - balanceBefore`. Баланс никогда не уходит в минус, но факт
недосписанной суммы не теряется молча — виден в истории и в отчёте платформы.

`preflightCheck` — обычное чтение баланса и сравнение с `estimateMaxCostCents`, без
блокировок (не защищает от гонки само по себе, это не его задача — его задача не звать
AI-провайдера впустую, когда денег точно не хватит).

### Мок-пополнение и VIP-бонус

`depositMock({ user, amountCents })`:
1. Валидация: `100 ≤ amountCents ≤ 100000` (т.е. $1–$1000).
2. `balanceCents += amountCents` (обычный `increment`, гонка тут не страшна — только рост).
3. `vipMonths = Math.floor(amountCents / 500)`; если `> 0` — `vipDays = vipMonths * 30`,
   `vipExpiresAt` продлевается от текущего `vipExpiresAt` (если он в будущем) или от `now`
   (если истёк/не задан) — тем же способом, что и `teacher/vip/activate/route.ts`.
4. Запись в `WalletTransaction` (`type: DEPOSIT`) и, если `vipMonths > 0`, запись в
   `VipTransaction` (`type: DEPOSIT`, `vipGrantedUntil` = новый `vipExpiresAt`).
5. Ответ: `{ balanceAfterCents, vipMonthsGranted, vipExpiresAt }`.

Реального платёжного провайдера нет — эндпоинт сразу считает деньги «оплаченными»
(это explicitly мок, см. манифест — интеграция bePaid отложена пользователем на будущий
заход и не входит в этот бриф).

**владельца комнаты** (`room.ownerId`/`room.ownerRole`), а не с того, кто физически нажал
кнопку на доске — ровно тот же субъект, с которого сегодня проверяется VIP.

### API

- `GET /api/wallet/balance` → `{ balanceCents, isVip, vipExpiresAt }` — текущий пользователь
  из сессии (роль по паттерну ADMIN→TEACHER, как в `getChatSessionUser()`, но своя копия
  внутри wallet-модуля — тот же паттерн уже продублирован в проекте в нескольких местах,
  не общий импорт из чат-модуля).
- `POST /api/wallet/topup` body `{ amountCents }` → `{ balanceCents, vipMonthsGranted, vipExpiresAt }`.
- `GET /api/wallet/transactions?cursor=&limit=` → курсорная пагинация (тот же паттерн, что
  `GET /api/chat/conversations/[id]/messages`), список `WalletTransaction` пользователя,
  новые сверху.

### UI

- `src/widgets/Wallet/WalletBadge/` — компактный бейдж баланса в `Header`, рядом с
  `ChatHeaderIcon`/`NotificationBell` (тот же слот верхней панели); поллинг раз в 15с —
  тот же интервал, что у бейджа непрочитанных чата, отдельный источник не изобретаем.
- `app/wallet/page.tsx` + `src/widgets/Wallet/WalletPage/` — текущий баланс крупно, форма
  пополнения (поле суммы в долларах, шаг $1, подсказка «от $5 — плюс месяц VIP»), список
  истории транзакций (депозиты зелёным, списания — с названием эндпоинта человеческим
  языком, напр. «Формула по фото»).
- i18n: новый namespace `Wallet` во всех 4 файлах `messages/{en,hi,ru,zh}.json` одновременно
  (действующее соглашение проекта) — заголовки, кнопка пополнения, тексты ошибок 402,
  подписи типов транзакций.

Швы для тестов — два, оба минимально необходимые (пытался свести к одному, но денежная
математика и атомарность списания — разные по природе риски, и оба денежные):

1. `pricing.computeCostCents` — чистая функция, юнит-тест на все 4 комбинации
   пик/непик × кэш-хит/промах + наценка.
2. `wallet.chargeForAICall` — проверка, что параллельные списания не уводят баланс в минус
   (условный `updateMany`), и что неуспешный AI-вызов не списывает вообще.

## Полный периметр «и так далее» из R04/R05

В брифе VIP-гейт для не-AI фич назван не полностью («кол-во юзеров в звонке, наличие
собственных курсов, сколько учеников и так далее») — по коду (`grep isVip`) весь остальной
периметр использования `isVip`/`vipExpiresAt`, помимо 7 AI-эндпоинтов из этого брифа, это:

- лимит участников видеозвонка (`app/api/call/rooms/limit`, `app/call/[room]/*`);
- видимость VIP-only постов и roadmap-ов (`app/api/post/*`, `app/api/roadmap`, `canViewPost`);
- профильные VIP-бейджи в карточках/профиле учителя (чисто отображение);
- существующая страница `/vip` и `teacher/vip/activate` — активация VIP по промокоду или
  реферальной ссылке (`applyPromoCode`, `applyReferralCode`) — это **не покупка VIP за
  деньги** (в коде нет ни одного реального платёжного вызова, `amount` там всегда `0`),
  а начисление бесплатных дней VIP за код/приглашение;
- админ-статистика (`admin/stats`, `admin/users`, `admin/content`) — подсчёт VIP как метрики.

Ничего из этого не входит в периметр этого брифа и не меняется. В частности, `/vip` и
`teacher/vip/activate` **остаются нетронутыми** — это не альтернативный способ «купить VIP
за деньги», который нужно было бы убрать ради R01, а промо-механика, которая как не была,
так и не будет платной. У R01 («вместо покупки VIP — пополнение баланса») буквально нечего
отключать: прямой платной покупки VIP в коде никогда не было, будущий платный вход — только
через баланс (пополнение) с бонусом сверху, а не через отдельный «купить VIP» флоу.

## Открытые места

- **Тариф на vision-модель** — код применяет ту же таблицу токенов, что и для текстовой
  модели DeepSeek. Если у `deepseek-v4-flash-vision-exp` другая реальная цена — поправить
  только `pricing.ts`, один файл.
- **Оценки `estimateMaxCostCents` по эндпоинтам** (потолок выходных токенов на LaTeX/план
  урока/тест из PDF и т.п.) — консервативные значения по здравому смыслу и текущим
  `maxTokens`/структуре ответа каждого эндпоинта, не измерены на реальном трафике. Если
  preflight будет слишком строгим (ложные отказы) или слишком мягким — поправить константы
  в `pricing.ts`.
- **`AI_MARKUP_PERCENT`** — переменная окружения, значение не задано (в `.env.example`
  пустое). Без значения наценка 0% — не ошибка, но и не бизнес-решение платформы, только
  сама себестоимость.
