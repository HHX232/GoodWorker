# 02 — Замена VIP-гейта на балансовый (5 эндпоинтов)

**Требования:** R06.1, R06.2, R06.4, R06.6, R06.7, G01, R03.1

**Зона:** `app/api/whiteboard/formula-ai/route.ts`, `app/api/whiteboard/formula-photo/route.ts`, `app/api/pdf-to-test/photos/route.ts`, `app/api/teacher/lesson-plan/route.ts`, `app/api/teacher/lesson-plan/revise/route.ts`
**Волна:** 2
**Status:** ready

## Что должно заработать

Пять эндпоинтов, которые сегодня отвечают 403 «VIP only» любому не-VIP пользователю,
вместо этого проверяют баланс: хватает денег на оценку стоимости — вызов идёт, после
успешного ответа AI списывается реальная стоимость. Не хватает — 402 с понятной суммой,
к AI-провайдеру запрос вообще не уходит. VIP-статус эти 5 эндпоинтов больше не проверяют
вообще (кроме `ADMIN`, который как и раньше проходит бесплатно — это служебная роль,
не платящий пользователь).

Для `formula-ai`/`formula-photo` платит владелец комнаты видеозвонка
(`room.ownerId`/`room.ownerRole`), а не тот, кто физически отправил запрос с доски —
ровно тот же субъект, с которого сегодня проверяется VIP.

Списание происходит **только** после успешного ответа от AI — упавший/оборвавшийся вызов
баланс не трогает (текущие `try/catch` в этих роутах уже возвращают ошибку без побочных
эффектов — сохранить это свойство).

## Критерии приёмки

- [ ] `formula-ai`, `formula-photo`: убрана проверка `!isVip && !isAdmin` → 403; вместо неё —
      `preflightCheck` на баланс владельца комнаты, вызов `callAI`/`callVisionAI`
      (новая сигнатура `{content, usage}` из тикета 01), затем `chargeForAICall`
- [ ] `pdf-to-test/photos`: убрана проверка «не-VIP → 403»; тот же паттерн preflight → вызов
      → списание, платит текущий `session.user` (ADMIN→TEACHER резолюция)
- [ ] `lesson-plan`, `lesson-plan/revise`: убрана проверка `role!==ADMIN && !isVip` → 403;
      `ADMIN` по-прежнему проходит без списания; TEACHER — preflight → вызов → списание
- [ ] Недостаточно средств → HTTP 402, тело `{error: "INSUFFICIENT_BALANCE", message, neededCents, availableCents}` — контракт ровно как в `interfaces.md`, AI-провайдер не вызывается
- [ ] Успешный AI-вызов без ошибки → ровно одно списание, форма успешного ответа каждого эндпоинта не изменилась (клиентский код `FormulaKeyboard`/`FormulaPhotoModal`/`LessonPlanModal`/`CalendarCreateModal` не требует правок)
- [ ] Ошибка AI-провайдера (сеть/таймаут/невалидный JSON) → баланс не списан, ответ 500 как и раньше
- [ ] Живая проверка через `curl` с сид-логином (`teacher@seed.dev`, изначально `isVip=false`): запрос к каждому из 5 эндпоинтов с нулевым балансом даёт 402; после мок-пополнения через `/api/wallet/topup` (из тикета 01) — запрос проходит и баланс уменьшается на ожидаемую сумму
- [ ] По возвращении — дописать в `interfaces.md` «Что построено», если сигнатуры чем-то отличаются от заявленных в тикете 01
