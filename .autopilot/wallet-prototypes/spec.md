# Спецификация: Кошелёк — три дизайн-варианта (дизайн-разведка)

## Задача

Пользователю (владельцу продукта) понравилась раскладка блоков с референс-скриншотов
финансовых дашбордов — крупный баланс, диаграмма статистики и список операций рядом,
и предложения прямо под балансом. Он хочет увидеть, как эта раскладка будет выглядеть
в трёх принципиально разных визуальных языках GoodWorker, чтобы выбрать сильнейшее
направление для будущей страницы «Кошелёк» репетитора — прежде чем строить её на
реальных данных.

## Решение

Три самостоятельные HTML-страницы, открывающиеся из браузера без сборки, с общим
компактным свитчером между собой (как в `catalog-a/b/c-*.html`). Каждая показывает
одну и ту же композицию — крупный баланс сверху слева, под ним предложения, справа
столбчатая диаграмма и список операций под ней — но в своём собственном визуальном
мире: объёмный «3D»-дашборд, строгие Ч/Б-блоки с маленьким акцентом, и третий —
тёплый редакционный «гроссбух»-стиль. Все данные — правдоподобные плейсхолдеры на
основе реальных продуктов GoodWorker (VIP, Pro-план, PDF→Тест, личные услуги), без
подключения к реальному API. Everything анимировано: появление блоков, диаграмма
рисуется, hover-состояния живые.

## Вариант A — «3D / Дашборд»

Референс — тёмный скриншот из брифа (карточки Visa, Statistic). Тёмная база
(`--bg` тёмный, не чистый чёрный — вроде `#12131a`), карточки — многослойные:
мягкая внешняя тень + внутренний блик, лёгкий `border-radius` покрупнее, местами
`backdrop-filter: blur` для стеклянного эффекта поверх декоративного градиентного
фона. Карточка баланса — с лёгким 3D-наклоном на курсор (`transform: perspective(...)
rotateX/rotateY` по `mousemove`, отключается на touch/`prefers-reduced-motion`).
Столбцы диаграммы — с градиентной заливкой и объёмной тенью, вырастают по скроллу.
Шрифт — тот же `sans` стек, что в существующих прототипах ГудВоркера (Archivo/Manrope
уже подключены в `ForNewDesign/prototypes/shared` мире — переиспользовать те же
Google Fonts `<link>`, не тянуть новые).

**Баланс — визуально карта** (из референса: «баланс на картах Visa»): плашка
баланса стилизована под платёжную карту — скруглённый прямоугольник альбомной
пропорции, декоративный чип (простая SVG-фигура, не логотип платёжной системы —
никаких реальных брендов/трейдмарков), частично замаскированный номер вида
«•••• •••• •••• 4821», сумма — крупно поверх карты. Без реального логотипа
Visa/Mastercard: это дизайн-мотив «карта», не имитация конкретного бренда.

**Анкер на «как щас главная»** — конкретно из `src/_pages/PublickPages/LandingPage/
LandingPage.module.scss`, чтобы не гадать, что именно переносить: многослойный
`box-shadow` у кнопок (пример: `0 12px 32px -14px rgba(237,6,6,0.6)` на hover —
`0 16px 36px -14px`, глубина растёт), фирменный красный акцент `$red` (`#ED0606`,
тот же токен, что `--red` в `offer-blocks-goodworker.html`) — использовать точечно
как акцент на самом ярком элементе (пиковый столбец диаграммы, позитивная сумма),
и декоративная точечная сетка фона (`radial-gradient(circle at 1px 1px, ...)`,
цвет адаптировать под тёмный `--bg`) как текстура за карточками. Палитра при этом
остаётся тёмной (per референс-скриншот), не светлой, как на самой главной —
переносится техника (тени/точки/акцент), не палитра.

**Кнопки Send/Request/Send Again из референса — сознательно не переносятся.**
Пользователь в тексте брифа явно перенаправил это место под другой контент:
«сразу под балансом можно все наши предложения расставить» — предложения
занимают ту зону, где на референсе были быстрые действия. Отдельного ряда
Send/Request нет ни в одном варианте.

## Вариант B — «Ч/Б / Классика»

Референс — вся остальная продуктовая вёрстка GoodWorker (сайдбар/шапка как в
`catalog-a-goodworker.html`). Светлый фон, чёрные/серые блоки, hairline-границы,
без теней или почти без них. Один акцентный цвет — использовать реальный акцент
GoodWorker (фиолетовый `#534AB7`, найден в `DashboardCenter.tsx`) точечно: активная
плашка предложения, положительная сумма в списке операций, столбец диаграммы под
курсором. Не заливать акцентом целые блоки. Переиспользовать те же токены/шрифты,
что `catalog-a-goodworker.html` (боковой навбар того же стиля — консистентность с
уже принятым продуктовым направлением каталога).

## Вариант C — «Гроссбух / Редакционный» (на усмотрение исполнителя)

Третий, принципиально другой от A и B: тёплая светлая бумага (`--bg:#f6f1e7` или
близко), крупные serif-цифры баланса (как в `variant-c-cinematic.html`/`v3-lab.html`
мире — Bodoni Moda для чисел, Archivo/Manrope для текста; переиспользовать тот же
Google Fonts `<link>`), тонкие рукописные разделительные линии вместо карточных
рамок, акцент — тёплая терракота/охра, использованная только в столбцах диаграммы
и в положительных суммах. Диаграмма выглядит как разлинованный гроссбух — столбцы
растут из общей базовой линии, подписи — moнospace-цифры как в чековой ленте.

## Свитчер

Собственный контракт, независимый от лендингового `nav[data-switcher]` и
`pdfland:scrollRatio` — по образцу `nav[data-catalog-switcher]` в
`catalog-a-goodworker.html`: маленький фиксированный `nav[data-wallet-switcher]`
с тремя ссылками на другие два файла + себя, `aria-current="page"` выставляется
инлайн-скриптом по имени текущего файла (10 строк, копия паттерна catalog, без
отдельного `shared`-JS-файла — свитчеру нечего синхронизировать между вариантами,
в отличие от лендинга со скролл-скрабом). Каждый файл подключает уже существующий
`shared/reveal-core.js` (`defer`, без изменений) для появления блоков по скроллу.

## Решения по реализации

- **Стек:** статический HTML/CSS/JS, инлайн в каждом файле, без сборки и npm —
  тот же стек, что весь `ForNewDesign/prototypes/` (см. `CLAUDE.md`). Почему:
  задача — визуальное сравнение, а не рабочая страница; 3D в варианте A — CSS-глубина,
  не WebGL, так что причины тянуть Next.js/пакеты (как у `footer-variants`) нет.
  Персонаж страницы — репетитор (владелец Pro-плана/PaymentReminder), не ученик:
  весь реальный контент для предложений (Pro-план, PaymentReminder-чеки) —
  преподавательский, смешивать со студенческим было бы противоречиво.
- **Расположение:** `ForNewDesign/prototypes/wallet-a-3d.html`,
  `wallet-b-mono.html`, `wallet-c-ledger.html` — рядом с `catalog-*`/`variant-*`,
  тот же прецедент.
- **Шрифты:** переиспользовать уже подключаемые в мире `ForNewDesign/prototypes`
  Google Fonts (Archivo/Manrope у swiss/каталога, Bodoni Moda у cinematic/v3-lab) —
  не подключать новых семейств, чтобы не плодить сетевые зависимости сверх
  уже принятых в этом мире.
- **Диаграмма:** ручной SVG/CSS bar chart (несколько `<div>`/`<rect>` с высотой
  в `%`/`transform: scaleY`, анимированной по `IntersectionObserver` из
  `reveal-core.js`) — без графических библиотек, конвенция «Ничего больше не
  подключать» из `CLAUDE.md`.

## Границы и швы

Один субагент = один файл, файлы полностью независимы по вёрстке/CSS/JS (как
`variant-a/b/c` и `catalog-a/b/c` — конвенция уже проверена в проекте). Общее
между ними — не код, а контракт, который должен совпасть дословно в трёх файлах:

| Что | Владеет | Выставляет (контракт, одинаковый в 3 файлах) | Прячет |
|---|---|---|---|
| Свитчер | каждый файл сам | разметка `nav[data-wallet-switcher]` с `data-wallet="a\|b\|c"`, `aria-current` через инлайн-скрипт по имени файла | стилизацию — своя в каждом мире |
| Мок-данные | каждый файл сам | один и тот же набор чисел/подписей раздела «Данные» выше, дословно | вёрстку/анимацию карточек — своя в каждом мире |
| Reveal | `shared/reveal-core.js` (существующий, не трогать) | `[data-reveal]` → класс `.is-in` | сам IntersectionObserver |

Тестовых швов нет — проект статический, без раннера; проверка — визуальный смоук
(см. ниже), как во всём `ForNewDesign/prototypes`.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R04 (реальный кошелёк/платежи) | нет модели баланса в БД и платёжного провайдера — задача явно про дизайн-разведку по расположению блоков, не про фичу; вживление в реальные данные — отдельный заход после выбора направления |
| Единая витрина-сравнение (по образцу `index.html` для лендинга) | не запрошена явно; свитчер между тремя файлами уже даёт сравнение в один клик, отдельная страница-агрегатор добавила бы четвёртый файл без новой ценности |

## Открытые места

Нет `placeholder`-строк в манифесте — все требования проработаны решениями выше
(режим semi/full, без блокирующих неизвестных: ни оплаты, ни хостинга, ни
аккаунтов эта задача не касается).
