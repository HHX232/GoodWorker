# Спецификация: Хранилище файлов репетитора

## Задача

Репетитор ведёт учеников годами и копит вокруг каждого горы материалов — методички, разборы, домашки, шаблоны. Сейчас единственный способ передать файл ученику — вложение в чат: оно тонет в переписке через неделю, не имеет структуры, и репетитор не может держать один и тот же файл открытым сразу нескольким ученикам без пересылки заново. Организованной, красивой полки для файлов со своей вложенностью и точечной выдачей доступа — нет.

## Решение

У VIP-репетитора в дашборде появляется вкладка «Файлы» — библиотека с папками произвольной вложенности (до 6 уровней), поиском по всей библиотеке, загрузкой файлов и предпросмотром PDF/изображений прямо в интерфейсе. Любую папку или отдельный файл можно расшарить сразу нескольким ученикам за один клик; расшаренное ученик видит у себя во вкладке «Файлы» и узнаёт о новом доступе карточкой-уведомлением в чате. Отдельно — «учебный» режим папки: репетитор разрешает ученикам сдавать в неё свои файлы, и у каждого ученика автоматически заводится личная подпапка, видная только ему и репетитору (как класс, где каждый сдаёт своё). Хранилище бесплатное до 7 ГБ на репетитора; сверх — ежемесячная плата за каждый гигабайт перелимита, списываемая с баланса Кошелька.

## Решения по реализации

**Модель данных** — два новых объекта-контейнера (`TutorFolder`, `TutorFile`) плюс два грант-объекта (`TutorFolderGrant`, `TutorFileGrant`), по образцу `TeacherStudent`/`Conversation` (composite id или `@@unique`, `onDelete: Cascade`, `String @id @default(uuid())`).

- `TutorFolder`: `id, teacherId, parentId? -> TutorFolder, name, allowStudentUpload Boolean @default(false), restrictedToStudentId? -> Student, ancestorIds String[], createdAt, updatedAt`. `ancestorIds` — список id всех родителей от корня, вычисляется один раз при создании (`[...parent.ancestorIds, parent.id]`); папки не двигаются между родителями (переименование — да, перенос — нет, см. «Вне рамок»), поэтому пересчитывать `ancestorIds` никогда не требуется. Это даёт проверку доступа/глубины за одну выборку без рекурсии.
- `TutorFile`: `id, teacherId, folderId? -> TutorFolder (null = корень), name, key, url, sizeBytes, mimeType, uploadedByRole (TEACHER|STUDENT), uploadedById, createdAt`.
- `TutorFolderGrant`: `folderId, studentId, grantedAt` — `@@id([folderId, studentId])`.
- `TutorFileGrant`: `fileId, studentId, grantedAt` — `@@id([fileId, studentId])`.
- Глубина: при создании папки — `parent.ancestorIds.length + 1 >= 6` → отказ (6 уровней считая корень первым уровнем).
- «Учебная» подпапка (G03): при выдаче `TutorFolderGrant` на папку с `allowStudentUpload=true` — транзакционно создаётся (если ещё нет) дочерняя `TutorFolder` с `restrictedToStudentId = studentId`, именем ученика, и собственным `TutorFolderGrant` только для этого ученика. Видимость: элемент виден ученику S, если (явный грант на него или на кого-то из `ancestorIds`) **и** ни у него, ни у кого из предков `restrictedToStudentId` не установлен в значение, отличное от S. Это правило само исключает подпапки других учеников из грант-каскада родителя, без отдельного механизма.
- Квота: `SUM(sizeBytes) WHERE teacherId = X` — обычный агрегат по требованию, без денормализованного счётчика (7 ГБ и разумное число файлов — агрегат дёшев; денормализация — если когда-нибудь станет узким местом).

**Доступ** — `src/shared/lib/tutorFiles/access.ts`, копирует форму `src/shared/lib/chat/access.ts`: `getFilesSessionUser()` (тот же ADMIN→TEACHER маппинг), `hasTeacherStudentLink`, `canStudentSee(fileOrFolder, studentId)` (правило выше), `requireOwnedFolder`/`requireOwnedFile` (гварды для API-роутов, паттерн `requireOwnedConversation`).

**Загрузка** — без изменений в `app/api/upload/route.ts`; новый вызов `uploadFile(file, 'tutor-files')` с клиента. После успешной загрузки сервер пишет строку `TutorFile` и возвращает актуальный `usedBytes` репетитора в ответе — по нему клиент решает, показывать ли модалку G02 (без отдельного GET-запроса).

**Биллинг (в ветке `feature/wallet-balance-topup`)** — переиспользует `src/shared/lib/wallet/wallet.ts`, ничего не переизобретает:
- `WalletTransactionType` — новое значение `STORAGE_OVERAGE_DEBIT`.
- `WalletSettings.storageOveragePriceCentsPerGbMonth Int @default(0)` — новое поле, тем же способом что `featuredPostsPriceCentsPerMonth`: добавляется в `getWalletPricingSettings`/`setWalletPricingSettings`, в `PATCH /api/admin/wallet-settings` (свои `MIN_/MAX_` константы) и в форму `WalletSettingsCard`. Значение `0` до тех пор, пока админ не впишет реальную цену — это и есть заглушка из «Открытых мест».
- `chargeStorageOverage(teacherId, overageGb, priceCentsPerGb, at)` в `wallet.ts` — по образцу `purchaseAddon`: атомарный `updateMany({ balanceCents: { gte } })`, при нехватке — списывает остаток до нуля (тем же приёмом «zero-floor», что уже есть в `chargeForAICall`, а не бросает `InsufficientBalanceError`, т.к. списание идёт из крона, без пользователя на том конце, см. G02.2). Пишет `WalletTransaction`.
- `app/api/cron/storage-overage-billing/route.ts` — тот же контракт, что `app/api/cron/close-stale-rooms`: `Authorization: Bearer ${CRON_SECRET}`, 401 без него. Раз в месяц (`vercel.json` → `"0 3 1 * *"`) проходит всех `isVip` репетиторов с суммой файлов > 7 ГБ, считает `overageGb = ceil((usedBytes - 7GB) / 1GB)`, вызывает `chargeStorageOverage`.
- Модалка предупреждения (G02) — переиспользует `InsufficientBalanceModal`'ы паттерн (portal в `#modal_portal`, `stopPropagation`), но это не «недостаточно средств», а информационное предупреждение о будущей плате — отдельный компонент `StorageOverageWarningModal` с той же механикой портала, ссылкой на `/wallet`.
- Уведомление о новом доступе — `CHAT_EVENT_TYPES` пополняется значением `FILE_ACCESS_GRANTED`; `EventCard.tsx` получает новую ветку рендера; выдача гранта вызывает `postEventCard()` (best-effort, как `HOMEWORK_ASSIGNED`).

**UI** — новый виджет `src/widgets/Files/` (по аналогии с `src/widgets/Chat/`): `FilesShell` (общий каркас: слева компактное дерево папок для быстрой навигации, справа — хлебные крошки, поиск, сетка карточек; на узких экранах дерево сворачивается в выпадающее меню), `FolderCard`/`FileCard` (карточки — форма из референса Floe, палитра и SCSS-модули GoodWorker, тёмная тема — блок `:global(html.theme-dark)` в конце файла по конвенции), `ShareAccessModal` (мультивыбор учеников), `FilePreviewModal` (PDF/изображения), `StorageOverageWarningModal`. Монтируется как вкладка в дашборде репетитора (рядом с существующими вкладками `DashboardCenter`) и как вкладка в дашборде ученика. Иконки — `src/widgets/Files/icons.tsx`, плоский реэкспорт `lucide-react` по образцу `Chat/icons.tsx` (`Folder`, `Search`, `Upload`, `Users`, `Download`, `FileText`…). i18n — новый namespace `files` во всех 4 `messages/*.json` одновременно.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `tutorFiles/access` | правила видимости/владения (включая правило подпапок G03.1) | `getFilesSessionUser()`, `canStudentSee()`, `requireOwnedFolder()`, `requireOwnedFile()`, `hasTeacherStudentLink()` (реэкспорт) | обход `ancestorIds`, ADMIN→TEACHER маппинг |
| `tutorFiles/storage` (модель + квота) | Prisma-модели `TutorFolder/TutorFile/*Grant`, подсчёт `usedBytes` | CRUD-функции над папками/файлами/грантами, `getUsedBytes(teacherId)` | создание «учебных» подпапок при выдаче гранта |
| `wallet` (расширяется) | баланс, `WalletTransaction`, ценообразование | `chargeStorageOverage()` (новая), существующие `purchaseAddon`/`chargeForAICall`/`insufficientBalanceResponse` | атомарность списания, zero-floor |
| `app/api/tutor-files/*` | HTTP-контракт над `tutorFiles/access` + `tutorFiles/storage` | REST-эндпоинты (папки, файлы, гранты, поиск, usage) | — (тонкий слой) |
| `app/api/cron/storage-overage-billing` | ежемесячный проход по перелимитным репетиторам | `GET` с `CRON_SECRET` | — |
| `widgets/Files` | вся отрисовка (обе стороны — репетитор/ученик) | `<FilesShell role="teacher"|"student">` | вёрстку карточек, модалок, предпросмотра |

Швы для тестов: `tutorFiles/access` (правила видимости — самое рискованное место, юнит-тестами по `canStudentSee`) и `wallet.chargeStorageOverage` (денежная логика — юнит-тест на zero-floor и на обычное списание). Остальное проверяется через API-роуты end-to-end, без отдельных швов.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Перенос папки/файла в другого родителя (drag&drop-реорганизация) | не упоминалось в брифе и не спрашивалось отдельно; без переноса `ancestorIds` можно не пересчитывать — сильно упрощает и доступ, и подсчёт глубины |
| Версионирование файлов (замена с историей) | не упоминалось; повторная загрузка — это новый файл с новым именем/датой |
| Массовые операции (выбрать несколько файлов и удалить/расшарить разом) | не упоминалось; расшаривание уже мультивыбор по ученикам, а не по файлам |
| Перенос долга за не полностью оплаченный месяц на следующий | не упоминалось; принята простая модель «платишь только за прошедший месяц, недоплата не копится» (G02.2) |
| Реальный платёжный провайдер в `depositMock` | вне этой фичи — Кошелёк уже принял это ограничение до нас (`POST /api/wallet/topup` — заглушка), просто наследуем |
