# 0028. Классы разбора партии — по потере вероятности выигрыша, а не сантипешек

**Контекст**
Разбор партии должен показывать классы как у chess.com (блестящий, отличный, лучший… зевок) и точность сторон; живой тренер уже классифицирует ход по потере в сантипешках.

**Решение**
Чистая модель `reviewModel.ts` переводит оценку в win% = 50 + 50·(2/(1+e^(−0.00368208·cp))−1) с точки зрения сходившего и классифицирует по потере win%: превосходный ≤ 2 %, хороший ≤ 5 %, неточность ≤ 10 %, ошибка ≤ 20 %, зевок > 20 %, плюс книжный, лучший, блестящий, отличный, упущение. Точность — по формуле от средней потери win%. Живой тренер в партии остаётся на пяти классах по сантипешкам.

**Почему**
Сантипешки в разборе отвергли: потеря 300 cp при +10 ничего не меняет, а при 0 — проигрывает партию; без нормализации выигранные позиции были бы усыпаны «зевками». Сразу перевести и живого тренера на win% отвергли — это меняет поведение уже принятой функции, а разбор шёл отдельным тикетом.

**Последствия**
В продукте две шкалы: один и тот же ход может быть «ошибкой» в партии и «неточностью» в разборе. Константы взяты из открытых описаний Lichess/chess.com и не калибровались на наших данных. Классы зависят от глубины анализа в браузере (MultiPV 2, ~0,6 с) — на другом устройстве разбор той же партии может отличаться.
