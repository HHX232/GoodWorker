# 0023. Лимиты объяснений тренера: гость 5, вошедший 100, VIP без лимита в сутки

**Контекст**
«Бесплатный» тренер тратит деньги на DeepSeek; пользователь задал только «маленький / большой / без лимита».

**Решение**
Лимит через существующий `checkRateLimit` (таблица `RateLimit`): ключ `chess-coach:ip:<ip>` для гостя (5/24 ч), `chess-coach:user:<id>` для вошедшего (100/24 ч); VIP (`isVip && vipExpiresAt > now` у Student или Teacher) не проверяется. Попытка списывается только после успешного ответа модели. При исчерпании — 429 с `tier`, оценка движком продолжает работать. Числа — константы в одном файле.

**Почему**
Без лимита отвергли — открытая дверь для выжигания бюджета. Отдельную таблицу счётчиков отвергли — `RateLimit` уже решает ровно эту задачу. Списание до вызова отвергли: сбой DeepSeek съедал бы попытку у пользователя, который ничего не получил.

**Последствия**
Списание после ответа даёт гонку: параллельные запросы на последней попытке могут пройти сверх лимита (принято как допустимое перерасходование). Гость за NAT делит 5 объяснений с соседями по IP, а смена IP обходит лимит. Числа 5/100 — предположение, а не решение пользователя.
