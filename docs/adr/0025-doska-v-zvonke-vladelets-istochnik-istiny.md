# 0025. Доска в звонке синхронизируется через data channel, владелец — источник истины

**Контекст**
В звонке с предметом «Шахматы» нужна общая доска: ходы видят все, опоздавший получает текущую позицию.

**Решение**
Новый режим главного слота `mode: 'chess'` рядом с `'whiteboard'`. Сообщения `call_chess_start/state/move/stop` идут по существующему data channel LiveKit. Не-владелец шлёт только `call_chess_move`; владелец валидирует ход через `chess.js` и рассылает `call_chess_state {fen, lastMove, moveAllowed, seq}`. Новый участник получает state тем же путём, что и доска-рисовалка. Кнопка видна при `subjectSlug === 'chess'` из API комнаты.

**Почему**
Хранить партию звонка на сервере отвергли — нужен был бы новый API и опрос, хотя канал между участниками уже есть. Равноправный обмен ходами (каждый применяет у себя) отвергли — одновременные ходы разводят позиции без арбитра. Отдельный канал/сокет отвергли — повтор уже работающего механизма доски-рисовалки.

**Последствия**
Если владелец вышел, доска замирает: применить ход больше некому. Позиция живёт только в памяти участников — после звонка партия не сохраняется. Права («ходят все / только я») проверяются у владельца, а не на сервере, — это честность внутри звонка, а не защита.
