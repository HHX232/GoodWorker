# 0026. Онлайн-партии на опросе раз в ~1 с; сервер — источник истины, ход — условным update под advisory-lock

**Контекст**
Нужны онлайн-партии с контролем времени, подбором по Эло и игрой по ссылке; реалтайм-инфраструктуры в проекте нет (чат тоже на опросе, см. 0010).

**Решение**
Клиент опрашивает `GET /api/chess/games/[id]?since=<ply>` раз в ~1 с. Сервер хранит партию в `ChessGame` (ходы UCI-строкой, `whiteMs/blackMs`, `turnStartedAt`), валидирует ход `chess.js`, списывает время и проверяет флаг и при ходе, и при чтении. Ход принимается условным update по ожидаемому `ply`, конкурирующие записи по одной партии сериализуются advisory-lock'ом Postgres. Контролей ровно три: `1+0`, `3+2`, `10+0`.

**Почему**
WebSocket/SSE отвергли — в проекте нет реалтайм-инфраструктуры, и заводить её ради одной функции дороже, чем опрос по уже принятому паттерну чата и звонка. Доверять часам клиента отвергли — флаг можно было бы не признать. Оптимистичную запись без блокировки отвергли: двойной клик и параллельный запрос второй вкладки применяли бы ход дважды или против устаревшей позиции; условный update по `ply` отбивает устаревший ход, lock — гонку внутри транзакции.

**Последствия**
Задержка хода у соперника — до ~1 с плюс сеть; для пули `1+0` это ощутимо, премувов нет. Каждая открытая партия — запрос в секунду на сервер и БД. Время списывается по серверному `turnStartedAt`, так что задержка сети игрока идёт в его часы. Тренер в онлайне выключен — иначе это подсказчик в рейтинговой игре.
