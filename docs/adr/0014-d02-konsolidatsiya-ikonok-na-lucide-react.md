# 0014. D02 — иконки чата консолидированы на lucide-react, дубли SVG устранены отдельным тикетом

**Контекст (что план предполагал)**
Тикеты T02/T03/T04/T06 создавались независимо, каждый в своей зоне (список чатов, диалог, композер, точки входа). План не давал явного указания, откуда брать иконки, и не включал проверку по ходу выполнения на предмет того, есть ли в проекте уже готовый набор.

**Решение (что код доказал)**
Craft-ревью после T02/T03/T04/T06 обнаружило, что весь `src/widgets/Chat/` и точки входа T06 рисовали SVG-иконки вручную (back/paperclip/message-bubble/stop/close/download), хотя в проекте уже установлен и используется `lucide-react` (`InfoFileListEditor.tsx`) — восемь копий одной и той же задачи по четырём тикетам. Отдельным тикетом T07 все дубли заменены на `lucide-react`.

**Почему**
Рассмотрели вариант «оставить как есть, раз визуально работает» — отвергли: дублирование одной и той же иконки в четырёх независимых местах компаундится при любой правке (толщина линии, viewBox, hover-состояние) — исправление потребовало бы ручной синхронизации 4+ файлов вместо одного импорта.

Рассмотрели точечное исправление только в будущих тикетах, без ретроактивной замены уже написанного — отвергли: в кодовой базе остались бы два стиля иконок одновременно (нарисованные вручную под старые тикеты и `lucide-react` под новые) без видимой причины для того, кто придёт после и не будет знать историю разбора.

**Последствия**
Изоляция тикетов по зонам ответственности (каждый не трогает файлы другого) сама по себе не ловит «завели ли несколько тикетов параллельно N копий одного и того же примитива» — это вскрывается только последующим craft-ревью, не самим планом декомпозиции. Для будущих прогонов с несколькими параллельными UI-тикетами это системный риск: договорённость об общем наборе примитивов (иконки и подобное) стоит фиксировать до декомпозиции на тикеты, а не полагаться на ревью постфактум.
