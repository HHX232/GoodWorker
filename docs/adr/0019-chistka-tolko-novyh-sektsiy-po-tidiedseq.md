# 0019. Чистка мусора идёт только по новым секциям, граница — tidiedSeq

**Контекст**
Раз в несколько минут DeepSeek должен убирать из конспекта бытовые и технические реплики, повторы и галлюцинации распознавателя. Бриф требует делать это «с умом», не перечитывая весь текст каждый раз. За час урока конспект становится большим.

**Решение**
В `LectureNote` хранится `tidiedSeq`. Когда `seq − tidiedSeq ≥ 3`, модель получает блоки только тех `aiSection`, у которых `toSeq > tidiedSeq`, плюс контекст. Ответ — `{remove:[n], replace:[{n, markdown}]}`; операции применяются только внутри этих секций, пустая секция удаляется, секции с `edited` не трогаются. После прохода `tidiedSeq = seq`. Финал делает дочистку тем же способом.

**Почему**
Отвергли чистку всего документа на каждом проходе: стоимость растёт с длиной урока, ответ модели хуже на длинном входе, а уже вычищенный текст перечитывается впустую и может быть «улучшен» повторно. Отвергли чистку каждого тика в момент добавления: у модели нет окружающего контекста, и она режет то, что по соседним репликам оказалось по теме. Окно из нескольких тиков даёт модели контекст без полного перечитывания.

Граница хранится в БД, а не в клиенте: тики могут прерваться и возобновиться, а серверное состояние переживает перезагрузку вкладки владельца.

**Последствия**
Мусор, который стал очевиден только позже (например, тема урока выяснилась через 10 минут), в уже вычищенных секциях остаётся: второго шанса у них нет. Ошибочное удаление необратимо, потому что хранится только текущий документ. Нумерация блоков для модели — «плоский список» в порядке документа, поэтому логика удаления зависит от стабильного порядка обхода (`docOps`) и должна покрываться самопроверкой при любой правке структуры секций. Секции, которые пользователь успел отредактировать, чистка не затрагивает, и мусор в них остаётся.
